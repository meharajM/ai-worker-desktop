# M03b — LangChain.js + LangGraph.js replacement proof

Status: `in progress → checked`; M03c WKWebView provider/graph assertions remain pending. This report replaces the obsolete AI SDK M03b record; it does not claim framework compatibility in a native WebView.

## Implementation

- Replaced direct `ai` / `@ai-sdk/openai-compatible` dependencies with exact direct pins: `@langchain/core` 1.2.17, `@langchain/openai` 1.6.2, and `@langchain/langgraph` 1.4.21. `package-lock.json` resolves `openai` 7.32.0, `langsmith` 0.10.11, `@langchain/langgraph-checkpoint` 1.1.6, and `@langchain/langgraph-sdk` 1.12.3; project Zod is 4.2.1. Checkpoint/SDK are transitive only; no graph server or checkpointer is imported.
- Public imports used: `@langchain/openai` (`ChatOpenAI`); `@langchain/core/messages` (BaseMessage classes and official stored-message mappers); `@langchain/core/tools` (`tool`); `@langchain/langgraph` (`StateGraph`, `StateSchema`, `MessagesValue`, `START`, `END`); and `@langchain/langgraph/prebuilt` (`ToolNode`).
- Installed package exports inspected: LangGraph root selects `dist/web.js` under its `browser` condition; `/prebuilt` and the Core/OpenAI modules resolve through declared ESM exports. Official docs used: [LangChain.js provider and model configuration](https://docs.langchain.com/oss/javascript/concepts/providers-and-models), [message serialization](https://docs.langchain.com/oss/javascript/langchain/messages), and [LangGraph workflows and agents](https://docs.langchain.com/oss/javascript/langgraph/workflows-agents). Package metadata/source and Vite output were inspected separately; docs alone are not browser compatibility proof.
- `proof-transport.ts` retains the typed Channel → bounded `ReadableStream<Uint8Array>` → standard `Response` seam. It caps bytes at 4 KiB, acknowledges native start before sending cancel, cancels once, removes abort listeners on terminal paths, and drops late events. Provider owns no SSE parser: `ChatOpenAI` uses explicit Chat Completions (`useResponsesApi: false`, `streaming: true`), custom fetch, fixture-only API key, no retries, and a fixed invalid base URL with no fallback.
- `proof-graph.ts` uses `StateGraph` / `MessagesValue`, one explicit model node, official `ToolNode`, and conditional model → tools → model routing. The fixture assistant turn emits two distinct tool calls; `ToolNode` returns two native results before the model's final text. Graph recursion is capped at six supersteps; `AbortSignal` and config flow into model and tool nodes. Empty callbacks disable tracing exports.
- `proof-history.ts` uses official LangChain stored-message mapping, limits encoded data to 16 KiB, validates bounded JSON records and the closed proof tool name/action before reconstruction, then feeds restored messages plus a new user turn into another graph invocation. It never calls the class-instantiating `load()` helper.
- Native fixture correction: response IDs now use each validated `runId`; LangGraph merges message updates by ID, so the old constant `id: "proof"` could replace earlier assistant turns. `ProofEvent` now serializes data fields as camelCase (`runId`), matching the renderer DTO. Tests cover every event variant and preserve split UTF-8 bytes. This corrects two existing M03a transport-contract mismatches exposed by reviewing the actual Channel payload path.
- `architecture.md` records the isolated module contracts. Main capability still grants only `allow-status`; proof config selects a separate capability granting only `allow-status` plus the three fixed proof commands. `build.rs` derives the native command manifest from the Cargo `proof` feature. Fresh ACL selection was checked against `tauri-build` 2.7.1 `src/acl.rs:451-460`: it resolves and validates only capability files named in the selected config. Existing autogenerated permission TOMLs do not grant commands by themselves. Default and proof Cargo configurations both checked successfully.
